## 2. 项目背景与目标

### 2.1 背景
需要一个个人品牌展示站点，用于集中展示个人简介、技能、项目作品和联系方式，方便招聘方、合作方和同行快速了解个人能力与项目经验。

### 2.2 核心目标
1. 5 秒内让访客理解“我是谁、我做什么、如何联系我”。
2. 清晰展示 3–6 个代表性项目，突出技术栈与项目链接。
3. 提供流畅、现代、深色主题的浏览体验，移动端可正常使用。
4. 具备基础 SEO、性能与可访问性，便于分享和搜索收录。

### 2.3 成功指标
- 首屏加载 LCP < 2.5s。
- Lighthouse 性能 / 可访问性 / SEO 均 ≥ 90。
- 移动端无横向滚动、无布局错乱。
- 项目卡片和联系方式点击率可追踪（如接入统计工具）。

### 2.4 非目标
- v1.0 不开发后台 CMS。
- v1.0 不支持多语言。
- v1.0 不包含博客系统，除非后续扩展。
- v1.0 不包含用户登录、评论、表单提交后端。

## 3. 目标用户与使用场景
- 招聘方 / HR：快速查看个人简介、技能和项目经历。
- 技术面试官：查看项目技术栈、链接和代码仓库。
- 潜在合作方：了解能力范围并获取联系方式。
- 同行 / 访客：浏览作品并访问 GitHub 或社交媒体。

---

## 4. 信息架构与页面结构

建议采用**单页锚点导航 + 可选项目详情页**：

- `/` 首页
  - Hero：大标题 + 简介 + 头像 + CTA
  - About：详细介绍 + 技能列表
  - Projects：项目卡片列表
  - Contact：邮箱、GitHub、社交媒体
- `/projects/[slug]` 项目详情页：P1 可选
- 顶部导航：Logo / 首页 / 关于 / 项目 / 联系
- 移动端：汉堡菜单或简化锚点导航

导航锚点：`#home`、`#about`、`#projects`、`#contact`。

## 5. 功能需求

### 5.1 首页 Hero
**优先级：P0**

内容字段：
- 大标题：姓名或核心定位，如“前端工程师 / 产品型开发者”。
- 一句话简介：1–2 句，说明方向、经验、兴趣。
- 头像：圆形或圆角矩形，支持 WebP/AVIF。
- CTA 按钮：查看项目、联系我。
- 可选：当前状态，如“开放远程合作”。

交互：
- 首屏内容渐入动画。
- CTA 平滑滚动到对应区块。
- 头像加载失败时显示占位图。

验收：
- 移动端首屏不出现文字截断。
- CTA 可键盘聚焦，焦点样式可见。

### 5.2 关于我
**优先级：P0**

内容：
- 详细介绍：2–4 段，包含背景、方向、经历、兴趣。
- 技能列表：按类别分组，如前端、后端、工具、设计。
- 可选：熟练度标签，如“熟练 / 熟悉 / 了解”，不建议使用无意义百分比进度条。

交互：
- 滚动进入视口时淡入上移。
- 技能标签支持 hover / focus 状态。

### 5.3 项目展示
**优先级：P0**

项目卡片字段：
- 项目名称
- 项目截图，建议 16:9，支持懒加载
- 简短描述：1–2 句
- 技术栈标签
- 项目链接：线上地址 / GitHub
- 可选：角色、时间、亮点、成果指标

卡片交互：
- hover 时轻微上浮、边框高亮或图片缩放。
- 整卡可点击时需明确可点击区域；外部链接新窗口打开并加 `rel="noopener noreferrer"`。
- 无链接时显示“暂无公开链接”，避免死链。
- 可选筛选标签：全部 / 前端 / 全栈 / 开源。

验收：
- 3–6 个项目在桌面端两列或三列展示，移动端单列。
- 图片有 alt 文本，缺失时使用项目名。
- 卡片高度自适应，不因描述长度错乱。

### 5.4 联系方式
**优先级：P0**

内容：
- 邮箱：`mailto:` 链接。
- GitHub 链接。
- 社交媒体链接：LinkedIn / X / 掘金 / 知乎等，按需配置。
- 可选：复制邮箱按钮，复制成功 toast 提示。

交互：
- 外链新窗口打开。
- 邮箱可考虑简单防爬处理，但不能影响可访问性。
- 移动端链接触控区域 ≥ 44px。

### 5.5 全局导航与页脚
**优先级：P0**

- 顶部导航吸顶，带半透明模糊背景。
- 当前区块高亮。
- 移动端菜单可展开 / 收起，支持 Esc 关闭。
- 页脚：版权、备案信息（如需）、返回顶部。

## 6. 设计要求

### 6.1 视觉风格
- 简洁现代，深色主题为主。
- 建议色板：
  - 背景：`#0B0F17`
  - 卡片：`#121826`
  - 主文字：`#E5E7EB`
  - 次文字：`#9CA3AF`
  - 强调色：`#3B82F6` 或 `#22D3EE`
  - 边框：`rgba(255,255,255,0.08)`
- 字体：系统字体优先，或使用 1 款无衬线字体，最多 2 个字重。
- 圆角：8–16px；卡片阴影克制，避免重阴影。
- 对比度满足 WCAG AA。

### 6.2 响应式
- 断点：移动端 < 768px，平板 768–1024px，桌面 > 1024px。
- 移动端单列布局，导航简化。
- 图片自适应，禁止横向滚动。
- 字号使用 `clamp()` 实现流式缩放。

### 6.3 动效
- 首屏渐入、滚动显现、卡片 hover、锚点平滑滚动。
- 使用 IntersectionObserver 实现滚动动画，避免监听 scroll 高频计算。
- 动画时长 200–500ms，缓动自然。
- 必须支持 `prefers-reduced-motion`，用户减少动态时关闭非必要动画。
- 动画不得阻塞内容可见性，禁用 JS 时内容仍可阅读。

## 7. 内容与数据规范
- 项目数据建议使用 JSON / Markdown / MDX 管理，便于后续迁移 CMS。
- 每个项目必须包含：名称、描述、技术栈、截图、链接状态。
- 图片统一压缩为 WebP/AVIF，提供宽高避免 CLS。
- 社交链接集中配置，避免硬编码散落。

---

## 8. 非功能需求

### 8.1 性能
- LCP < 2.5s，CLS < 0.1，INP < 200ms。
- 首屏图片优先加载，非首屏图片懒加载。
- 字体子集化或使用系统字体。
- 代码分割，避免引入大型动画库。

### 8.2 SEO
- 每页独立 title、description。
- Open Graph / Twitter Card 分享图。
- 语义化 HTML：header、nav、main、section、footer。
- 生成 sitemap.xml、robots.txt。
- 可选：Person JSON-LD 结构化数据。

### 8.3 可访问性
- 所有图片有 alt。
- 键盘可访问导航、按钮、链接。
- 焦点样式清晰。
- 颜色对比度达标。
- 动效尊重减少动态偏好。

### 8.4 兼容性
- 支持最新版 Chrome、Safari、Firefox、Edge。
- 支持 iOS Safari 和 Android Chrome。
- 不支持 IE。

### 8.5 分析与部署
- 可选接入 Plausible / Umami / GA4。
- 部署到 Vercel / Netlify / Cloudflare Pages。
- 配置自定义域名和 HTTPS。

## 10. 验收标准

1. 桌面端和移动端均可完整浏览四个核心区块。
2. 所有项目卡片字段完整，链接可点击且无死链。
3. 移动端无横向滚动，导航可正常展开关闭。
4. 滚动动画流畅，低性能设备不卡顿，减少动态模式生效。
5. Lighthouse 性能 / 可访问性 / SEO ≥ 90。
6. 页面 title、description、OG 图配置完整。
7. 键盘可完成导航、CTA、项目链接和联系方式访问。
8. 图片均有 alt，图片加载不引起明显布局偏移。
9. 部署后 HTTPS 正常，404 页面友好。

## 12. 风险与待确认

### 风险
- 项目截图缺失导致视觉不完整。
- 动画过多影响低端移动设备性能。
- 社交链接变更导致死链。
- 深色主题对比度不足影响可读性。

### 待确认
1. 采用单页锚点还是多页面结构？
2. 项目数量及是否有详情页需求？
3. 是否需要博客 / 多语言 / CMS？
4. 是否接入访问统计？使用哪种工具？
5. 域名、部署平台、备案信息是否已确定？
